# WorkBuddy Portable 1.0.2：测试与验收

日期：2026-09-27。范围为启动器 UI / 生命周期更新；运行时适配保持 **1.0.1**。

## 本次实现

- 正文 22、标题 32、辅助 18 逻辑像素（此前 16 / 24 / 14）；窗口重排，按系统 DPI 缩放并限制到工作区。
- 独立的可见进度 HWND 与不可见控制端点。收到真实主界面的 ready nonce 后销毁可见窗口与控件；无 Shell_NotifyIcon / 启动器托盘逻辑，不以隐藏或最小化充当关闭。
- 内部控制端点保留消息 / 设备事件能力，不出现在任务栏或托盘。后台检查更新不重新打开启动器；明确同意安装更新时重新创建准备窗口。
- `--settings` / Network-Settings.cmd 独立打开设置，在应用锁之前处理，不启动第二个应用；保存后下次启动或重试生效。
- 以受管桌面根进程的退出为依据，**不是窗口可见性 / 最小化事件**。退出时终止本次 Windows Job 并等待 ActiveProcesses==0，再关闭桥接与临时资源。
- Job 仍为 KILL_ON_JOB_CLOSE，无 breakaway 权限；子进程先挂起、入 Job、再恢复，延续原有保护。不按进程名 / taskkill /IM 批量终止。
- Worker 的 defer 清理完成后才发送最终退出消息，主函数也等待 worker。启动后的异常退出记录日志并自动结束监管；启动前失败仍可显示错误和重试。
- ready 轮询间隔内快速退出时再次检查 nonce，避免误报“未打开”。取消时等待有界；清理不确定时保留错误记录，不宣称已安全回收。
- 不再有阻塞的“已退出”成功消息框。正常退出清理本次 Data/Run 子目录及 Data/Temp；会话、日志、配置、缓存和运行时保留。

## Windows 现场验收步骤

1. 先备份旧目录；覆盖 EXE 与 Network-Settings.cmd，保留 Data / Runtime / tools / portable.json。确认此次 UI 升级没有重新下载或适配有效的当前运行时。
2. 在 100%、125%、150%、200% 缩放及较小屏幕检查启动正文、长路径/错误信息、代理设置控件是否可读。长错误详情也保存在 Data/Logs；不以编译通过代替目测。
3. 主界面真正打开后，Alt+Tab / 任务栏 / 托盘不应有**启动器**窗口或图标；官方应用自己的图标可以存在。任务管理器中仍有必要的无界面启动器进程，这是正常的。
4. 最小化、隐藏到应用托盘、或在退出确认中点取消：应用 / 代理和任务应继续正常工作。
5. 在应用自身菜单 / 官方托盘选择真正退出。处理保存提示后，确认本次应用、daemon / CLI 等受管子孙进程及启动器都结束；无需点击任何启动器成功弹窗。不要只按“×”就认定已退出。
6. 对另一个便携目录/已安装实例做隔离检查，它们不应被本次退出按名称误杀。检查后台监听端口及本次 Data/Run 目录已释放。
7. 主程序运行时打开 Network-Settings.cmd，应只有设置工具，没有第二个官方应用。保存退出设置工具，配置应在下次启动生效。
8. 重试、明确安装更新、首次慢启动、正在启动时取消和应用崩溃路径需要现场复测。不要为测试清理而在真实任务中强拔 U 盘。

## 边界

- 本次守护的是自身 Job 中的进程；Windows 服务、提升权限代理 / 系统 broker 或独立外部应用代为创建的进程，不承诺无条件纳入。不会为了“清干净”而扫杀全机同名进程。
- 正常退出后仍请使用 Windows“安全删除硬件”。第三方杀软/驱动持有文件、强拔盘、断电、内核或硬件异常不可能由这个启动器保证完全清理。
- 无零宿主痕迹、无任意跨机凭据迁移保证。账号权限、服务端规则、实际 AI 任务仍依赖官方服务及用户环境。
- 若清理/删除失败，检查 Data/Logs/launcher.log，不要将“根进程退出”或编译通过当成所有资源已释放的证据。

## Electron 完整性

原始 WorkBuddy.exe SHA-256：`6aa589e3edf1b91cd65d72f025def57689905505835c4c39481ed11f2b9e759c`。

原始 ASAR JSON header SHA-256：`07c5724186060f03529a7fdecf4195ac4b5c71dc4d6caa861f86dde019c52249`。

发现原 EXE fuse 数据为版本 1、长度 8、`10111101`：ASAR 完整性校验与 only-load-app-from-ASAR 均开启。不能只替换 ASAR 就宣称能启动。

处理方法：只在新 stage 中核验原 EXE 整文件哈希、资源段范围与两个明确的 ASAR 完整性资源记录；替换两处定长摘要。保持所有 fuse 原字节、原生代码及其余资源不变；清零 PE certificate directory / checksum，裁掉原签名表。**此副本不再有腾讯有效签名**，不把已失效签名留着冒充签名有效。安装包缓存不改动。

ASAR writer 保留原 payload 并追加修改模块，重新计算修改条目的块完整性。运行时指针记录适配后 EXE 与 ASAR 的整文件 SHA-256。结构检查覆盖根目录必要资源和全部 2,753 个 unpacked 叶子文件；43 个上游签名/打包后大小与 ASAR header 不同的文件，使用从固定安装包取得的实际大小表（`runtime_layout.go`），而非错误要求它们等于签名前大小。

这些本地记录用于一致性与损坏检测，不是抵御能修改 U 盘和元数据的本地攻击者的独立签名。

## 网络

沿用已交付 DSH 1.0.4 的 Go Windows 代理探测、PAC / WPAD 及 HTTP / HTTPS / SOCKS 传输架构，独立命名和随机桥接认证。不是改动或替换 DSH 发行目录。

- Chromium `resolveProxy` 只给 `PROXY host:port`，会丢失桥接认证。因此不能仅设置 HTTP_PROXY；本适配在原 `resolveProxyForUrl` 中返回带认证 URL，供 PAC 感知 Axios / Node agent 使用。`rawRule` 为固定无凭据文本。
- 默认及新增 Electron session 的 `setProxy` 固定使用桥接，防止后续初始化覆盖。只独占本桥接的 app/net.request 代理认证事件，其他认证事件交回原逻辑。
- 使用官方包内 Undici **6.25.0**，主进程与 daemon 同步建立代理；仅便携所有的 Agent / Pool / ProxyAgent 使用 HTTP/1.1，保留 HTTPS 证书验证、Node 根 CA、可用的系统/额外 CA、调用者显式指定的 dispatcher。
- 请求、响应、Authorization、Cookie、代理口令不由便携网络日志记录；目标仅记 origin，错误仅记归一化 code。官方应用和第三方工具自己的日志不作无敏感数据保证。

## 准备与复用

- 普通启动的有效本地记录在 feed 获取之前返回；不以启动器版本替换作为无条件重新下载的理由。
- 固定原始包缓存经哈希校验即可本地重新解包。新 stage 中全部操作成功后才原子切换 `current.json`；旧目录不删除。
- 未审核的新版官方包不下载、不执行，不假装已完成兼容适配。安装器执行路径被委派，而不是禁用服务端强制升级策略。
- 正常 Windows CreateProcess 在 suspended 状态先加入 kill-on-close Job，再恢复线程；编码为 UTF-16，非 cmd.exe 拼接。设备通知用 ReadProcessMemory 读取原生通知结构，避免 Go uintptr→pointer 的 vet 告警。
